# 1.2 Gaze hold/release trial

This records the first trial. Stuart's playtest accepted further exploration of hold/release and rejected its charge HUD and floating icons. [The crown feedback pass](1.2-gaze-crown-feedback.md) supersedes the presentation described here; charge timing and damage are unchanged.

Private experiment, October 5, 2026. Branch `codex/gaze-release-120`, based on installed candidate `d383879ba5ce2de6a1dcc1bb3c8269ace491a7b4`. Stuart selected up to three stored charges per surge, with early release and unused charges banked.

## Playable hypothesis

Keep the continuous beam and hover. After ignition, hold Primary to prepare one charge immediately, two at 0.45 seconds, three at 0.90 seconds. Release to fire one grouped surge; holding at three does not fire or start a second group. A fresh hold is available after 0.65 seconds. Entry-held input must first be released. Preparation and unlaunched intake remain refundable on exit.

The trial fixes beam duration at seven seconds and removes the per-spend duration extension and lasting damage ramp. Each surge deals 400% body damage per spent charge (400/800/1200%). These are experimental numbers, not accepted balance. The existing no-item-proc pulse rules, crit behavior, geometry, eight-victim limit and healing budget remain. A default five-charge bank still permits at most 5% base maximum-health recovery. Newly earned reserve cannot feed the same cast.

For scale, the ideal level-one, 1x attack-speed model gives approximately 3,500% core damage plus 2,000% from five charges, versus 8,897.5% core-plus-pulses in the old early-spend model. Zero-fuel core increases from about 2,000% to 3,500%. These exclude secondary targets, crits, Static and items, and are not measured DPS. This deliberately redistributes power; it is not a small numerical buff.

Drift increases from the configured multiplier by 10% (default 0.30 to 0.33). Hover height and steering remain. Controller comfort near enemies directly below is still an acceptance question.

The HUD shows three preparation slots and a separate remaining bank, above a fixed timer scale. Prepared crown orbs draw inward and enlarge; the crown opens progressively. Grouped release has three separate intake trails, a stronger travelling accent and existing authored surge sound tiers 1/3/5. The earlier continuous beam gets more width and less suppression during surges. Startup, beam loops and target-confirmed hit cues remain. This is not a newly recorded audio pass.

## Code organization

`GazeReleasePolicy.cs` owns timing and input edges. `GazeFuelController.Release.cs` authenticates owner input and uses server time. The main controller owns resource spending and recovery; `.Presentation.cs` handles received visual events. `GazeFuelSchedule` reserves groups while preserving the old one-orb API. `GazeReleaseHud.cs` separates the private trial UI from the old extension HUD.

`HS_GAZE_BASELINE=1` selects old mechanics for local comparisons. The default of this private build is the new trial. This switch is process-local, not synchronized. All peers must use matching builds/settings; remote-client multiplayer acceptance is outstanding. The private Gaze tooltip is explicitly labeled and temporarily shown in English for every language; published translations are untouched. The switch and trial text must be resolved before a public release.

## Release work still open

- Decide charge-generation rules in a separate comparison. This trial preserves existing generation, including ultimate-triggered Static and reserve gains. The recommendation remains to evaluate Arc Bolt/Stormspear generation without ultimate self-funding; the spear conductor currently intentionally generates none.
- Measure seeded random item inventories and controlled attack-speed/proc/healing builds. A shorter fixed beam changes cast damage, safety and cooldown-cycle throughput; this trial is not a balance certification.
- Judge aiming below the player and up again with a physical controller, listen to the mixed audio, and compare HUD readability at actual player settings.
- Isolate Open Circuit's spinning white artifact, extend terrain response with bounded raycasts, and give Circuit its own audio pass. No Circuit polish is claimed by this Gaze experiment.
- Verify remote ownership, packet timing, external skill overrides and mid-cast disconnects in multiplayer.

## Reproduce / roll back

Build `HollowSaintMod/HollowSaint.csproj` in Release. Run `tools/GazeReleaseChecks` and the relevant regression projects. Use `tools/dev-profile/Stage-Build.ps1` only while the game is closed. Then set `HS_SEGMENTS=gaze-release` and run `tools/dev-profile/Run-Autopilot.ps1 -Name <unique-name>`.

For the existing `GazePrimaryChecks` and `GazeHudChecks`, set `$env:HS_GAZE_BASELINE='1'` in the test shell. The HUD project also directly checks the new display. Run source-aware tests with `dotnet run --project tools/<name> -c Release -- .` from the repository root. Remove `Env:HS_GAZE_BASELINE` before the hold/release game test. Do not pass `--nologo` to `dotnet run`: source-aware test programs interpret it as their repository argument.
